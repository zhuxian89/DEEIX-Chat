# 微信公众号关键词能力管理

## 目标

把微信公众号从“代码中固定处理 `13003`”升级为可配置的关键词能力平台，首期重点支持：

- 关键词管理：新增、编辑、启用、停用关键词；
- 回复模板管理：维护公众号返回的文本内容；
- 注册码发放记录：查看 OpenID、注册码、状态和时间；
- 关键词处理日志：查看首次发放、重复返回和失败原因；
- 当前部署版本：复用现有 `/api/v1/version`，确认线上是否运行了目标镜像。

不修改既有 `users`、`registration_codes` 表结构，不把微信公众号的 AppID、AppSecret、Token 复制到业务管理页面。

## 核心抽象

### 1. 关键词规则

关键词规则是管理员配置的数据，负责把用户输入映射到一个功能和一个回复模板：

```text
keyword -> action -> reply template
```

示例：

```text
13003 -> issue_registration_code -> 注册码回复模板
HELP  -> help                  -> 帮助回复模板
```

规则约束：

- 关键词经过 `TrimSpace` 后精确匹配；
- 同一个关键词唯一；
- 支持多个关键词同时启用；
- 关键词停用后不再触发对应功能；
- 可以先启用新关键词，再停用旧关键词。

### 2. action 功能处理器

`action` 是后端内部的稳定功能枚举，不是管理员输入的代码，也不做脚本执行。

内部使用英文稳定标识，管理页面显示中文名称：

| action | 管理页面名称 | 首期状态 |
| --- | --- | --- |
| `issue_registration_code` | 发放注册码 | 实现 |
| `help` | 帮助说明 | 预留 |
| `query_registration_code` | 查询注册码 | 预留 |

新增业务能力时增加一个受控处理器；新增同类关键词时只需要新增规则和模板，不需要新增表结构。

每个 action 负责：

- 接收 OpenID、关键词和请求上下文；
- 执行业务逻辑；
- 返回模板变量；
- 返回处理结果和可选的注册码 ID；
- 声明该 action 允许使用的模板占位符。

首期只实现 `issue_registration_code`，继续使用现有 OpenID 幂等发码逻辑：同一 OpenID 永远返回第一次发放的注册码，不重复创建。

### 3. 回复模板

回复模板与 action 分离。action 决定业务数据，模板决定返回内容。

首期：

- 只支持微信公众号文本回复；
- 文本可以包含中文、英文、表情和 URL；
- 不支持 HTML/Markdown 富文本排版；
- URL 作为文本发送，是否被微信客户端识别为可点击链接由客户端决定；
- 使用占位符，例如 `{{CODE}}`；
- 模板不能引用关联 action 未声明的占位符；
- `issue_registration_code` 必须包含 `{{CODE}}`，并替换为注册码明文。

默认模板：

```text
你的专属注册码：{{CODE}}
```

图片、图文卡片、语音、视频等消息不是文本模板的扩展写法。后续支持时增加受控的 `response_type`（例如 `image`、`news`）和结构化字段，不在文本中嵌入任意 HTML 或脚本。

### 4. 处理日志

日志记录统一的关键词处理过程，而不是只设计“注册码日志”。注册码发放只是其中一种 action。

结果类型：

- `issued`：首次成功发放注册码；
- `replayed`：同一 OpenID 重复请求，返回原注册码；
- `handled`：其他 action 成功处理；
- `failed`：处理失败。

日志保存稳定的英文 action，不保存容易变化的中文显示名称。页面根据 action 注册表显示中文名称。

不记录未命中规则的图片、事件或普通文本消息，避免日志无限增长；不保存完整 XML、Token、AppSecret 或敏感配置。

## 回调处理流程

1. 校验微信签名。
2. 解析明文 XML；首期只处理文本消息。
3. 对 `Content` 执行 `TrimSpace`，查询已启用的关键词规则。
4. 没有匹配规则时返回成功空响应，不创建注册码。
5. 找到规则后调用对应 action 处理器。
6. action 返回模板变量和处理结果。
7. 校验并渲染回复模板，生成文本 XML 回复。
8. 写入关键词处理日志。
9. `issue_registration_code` 的注册码创建、发放关系和成功日志在一致性边界内完成；并发请求仍由 OpenID 唯一约束保证幂等。

如果后续需要调用微信用户信息接口获取昵称、头像或 UnionID，应作为独立能力：资料获取失败不能阻断注册码发放。

## 管理页面

在现有管理员区域新增“微信公众号管理”页面，使用 Tab 组织以下视图：

- 概览
- 关键词
- 模板
- 注册码发放记录
- 通用处理日志
- 绑定关系

### 概览

- 当前部署版本：复用 `/api/v1/version`；
- 已发放注册码总数；
- 最近成功和失败处理数量。

### 关键词管理

- 关键词；
- action 中文名称；
- 关联回复模板；
- 启用状态；
- 创建和更新时间；
- 新增、编辑、启用、停用。

关键词行内直接完成绑定：管理员在新增或编辑关键词时，同时选择 action 和回复模板，保存后形成一条完整规则：

```text
关键词 -> action -> 回复模板
```

一个关键词只能绑定一个 action 和一个模板；一个模板可以被多个使用相同占位符约束的关键词复用。

### 回复模板管理

- 模板名称；
- 回复类型，首期固定为 `text`；
- 模板内容；
- 启用状态；
- 占位符校验；
- 已绑定关键词数量和关键词列表；
- 在模板行内快捷绑定关键词，实际仍然写入关键词规则；
- 被启用规则引用的模板不能直接删除。

### 绑定关系

绑定关系页面用于查看所有“关键词 -> action -> 回复模板”的完整关系，作为运营总览：

- 关键词；
- action 中文名称；
- 回复模板名称和摘要；
- 启用状态；
- 创建和更新时间；
- 按关键词、action、模板和启用状态筛选；
- 提供“编辑关键词”和“编辑模板”跳转入口。

该页面是关键词规则的只读投影，不新增绑定表，也不允许在这里直接产生另一套关系数据。新增、修改和启停仍从关键词行或模板行执行。

### 注册码发放记录

直接查询现有 `wechat_registration_issuances`，关联 `registration_codes`，展示：

- OpenID；
- 注册码明文；
- 注册码状态：`active` / `used`；
- 注册码 ID；
- 首次发放时间；
- 按 OpenID、注册码搜索；
- 分页查询。

### 关键词处理日志

展示：

- 时间；
- OpenID；
- 关键词；
- action 中文名称；
- 处理结果；
- 关联注册码；
- 安全的错误摘要。

首期不做日志导出、告警和复杂清理策略。

## 数据结构

新增三张表，不修改旧表：

### `wechat_reply_templates`

- id
- name（唯一）
- response_type（首期固定为 `text`）
- content
- enabled
- created_at
- updated_at

### `wechat_keyword_rules`

- id
- keyword（唯一）
- action
- template_id
- enabled
- created_at
- updated_at

### `wechat_keyword_invocation_logs`

- id
- open_id
- keyword
- action
- template_id（可空）
- registration_code_id（可空）
- result
- error_code
- error_message
- created_at

现有 `wechat_registration_issuances` 继续作为 OpenID 与注册码的唯一发放关系来源，不复制注册码字段。

## 接口边界

新增接口全部放在管理员认证路由下，建议归属：

```text
/api/v1/admin/wechat
```

包含：

- 关键词规则列表、新增、编辑、启用、停用；
- 回复模板列表、新增、编辑、启用、停用；
- 发放记录分页查询和统计；
- 关键词处理日志分页查询和筛选。

公众号回调仍是公开接口，但只读取已启用的规则和模板，不能通过公众号请求修改管理数据。

## 迁移与兼容

- 应用启动时 GORM 自动迁移新增三张表；
- 首次迁移创建默认模板和默认规则：`13003 -> issue_registration_code`；
- 现有 `wechat_registration_issuances` 数据继续有效；
- 现有 `users`、`registration_codes` 表不做任何字段变更；
- 如果规则表尚未配置，服务端保留 `13003` 的兼容默认行为，避免升级瞬间停止发码。

## 安全边界

- 管理接口必须走现有管理员认证和权限；
- 不在页面展示或修改 AppSecret、Token；
- OpenID 只出现在管理员页面和受保护接口；
- 普通日志不打印注册码明文和完整 XML；
- action 必须来自后端注册表，禁止数据库内容直接变成可执行代码。

## 验收标准

1. 管理员可以新增、编辑、启用和停用关键词。
2. 停用 `13003` 后，发送 `13003` 不再触发其 action；启用新关键词后按新规则工作。
3. 管理员可以维护文本回复模板，注册码模板必须包含 `{{CODE}}`。
4. 同一 OpenID 使用新关键词仍返回原注册码，不重复创建注册码。
5. 管理员可以分页查看 OpenID、注册码、状态和发放时间。
6. 首次发放、重复返回、其他 action 成功和失败请求分别产生对应日志。
7. 发放记录和日志不能被公众号公开接口读取。
8. 启动迁移只新增三张表，不改变既有表结构。
9. `/api/v1/version` 在管理概览中显示当前线上构建版本。

## 已批准决策

1. 实现关键词规则、文本回复模板、注册码发放记录和通用处理日志。
2. action 使用英文稳定枚举，管理页面显示中文名称。
3. 首期只支持文本、表情和 URL 文本，不实现图片/图文卡片等媒体回复。
4. 第一阶段不在微信公众号管理页面重复实现手动发码、删除记录和日志导出；现有管理员手动发码功能保持不变。
5. 管理页面名称为“微信公众号管理”，采用 Tab：概览、关键词、模板、绑定关系、注册码发放记录、通用处理日志；绑定关系 Tab 只读展示规则关系，关键词行和模板行提供编辑入口。
