# 微信公众号注册码发放

## 目标

用户关注微信公众号后发送精确关键词 `13003`，公众号返回一个注册码。
同一个微信公众号用户只能领取一个注册码，用于现有网站注册流程。

这是微信公众号深度绑定的第一个长期集成功能，后续还会继续扩展公众号能力。

## 当前阶段

方案已获用户批准，功能实现和只读审查已完成；当前等待单独的提交和 push 授权。

此前工作区中曾产生过一版未审核的实现草稿；本次实现已按批准方案重新核对并完成校正。

## 已确认事实

- 现有注册码状态只有 `active` 和 `used`。
- 现有注册流程已经支持注册码消费。
- 不修改既有用户表结构。
- 新增独立表是允许的。
- 注册码明文显示是既有业务要求。
- 项目使用 GORM 启动迁移创建持久化表。
- 公众号回调需要公开 HTTP 地址，并由微信公众号服务器调用。

## 推荐方案

采用最小 MVP，先实现“按 OpenID 幂等发码”，暂不实现网站账号与微信身份的强绑定。

### 回调接口

- `GET /api/v1/wechat/callback`：微信公众号服务器首次配置时进行签名验证，验证成功返回 `echostr`。
- `POST /api/v1/wechat/callback`：接收明文 XML 消息。
- 首期只支持微信公众号明文消息模式，不实现 AES 加密消息模式。
- 首期只处理文本消息，内容 `TrimSpace` 后必须精确等于 `13003`。

### 发码流程

1. 校验微信签名。
2. 解析 XML，取得发送方 `FromUserName`，将其作为 OpenID。
3. 查询 `wechat_registration_issuances` 是否已有该 OpenID。
4. 如果已有记录，返回该记录关联的原注册码。
5. 如果没有记录，在同一个数据库事务内：
   - 生成唯一注册码；
   - 创建现有 `registration_codes` 记录，状态为 `active`；
   - 创建 OpenID 与注册码的发放关系。
6. 以 XML 文本消息返回明文注册码。

重复消息和微信重试请求必须返回同一个注册码，不得重复创建注册码。

### 数据结构

新增表 `wechat_registration_issuances`：

| 字段 | 约束 | 说明 |
| --- | --- | --- |
| `id` | 主键 | 发放记录 ID |
| `open_id` | 唯一、非空 | 微信公众号用户 OpenID |
| `registration_code_id` | 唯一、非空 | 关联现有注册码 ID |
| `created_at` | 非空 | 首次发放时间 |
| `updated_at` | 非空 | 更新时间 |

不新增或修改 `users`、`registration_codes` 的字段。

### 删除保护

已通过公众号发放的注册码不能被管理员删除，否则会出现公众号仍能返回注册码、但网站注册已无法使用的不一致状态。

实现时需要在删除路径增加引用检查，或通过数据库约束保证删除被拒绝；不能静默删除发放关系。

## 配置

新增静态环境变量：

```text
WECHAT_CALLBACK_TOKEN=微信公众号后台配置的 Token
```

微信公众号服务器地址：

```text
https://你的域名/api/v1/wechat/callback
```

消息加解密模式首期选择“明文模式”。

## 风险与保障

- 伪造请求：校验 `signature`、`timestamp`、`nonce`，比较签名时使用常量时间比较。
- 重复投递：OpenID 唯一索引 + 事务 + 冲突后重新查询。
- 并发发放：OpenID 唯一约束保证最终只有一条发放记录。
- 注册码冲突：生成失败或唯一冲突时重试，不能返回未落库的注册码。
- 请求体攻击：限制 XML 请求体大小。
- 日志泄漏：不在普通业务日志中打印注册码明文。
- 配置缺失：未配置 Token 时功能不应被视为可用，并应在部署文档中明确。

## 验收标准

1. 合法 GET 签名返回 `echostr`。
2. 错误签名、缺少 Token、缺少参数时请求被拒绝。
3. 合法文本 `13003` 首次请求返回一个 `active` 注册码。
4. 其他文本、图片或事件消息不会创建注册码。
5. 同一个 OpenID 重复发送始终返回第一次的注册码。
6. 两个不同 OpenID 获得不同注册码。
7. 并发请求不会创建多个发放记录或多个可用注册码。
8. 公众号发放的注册码能完成现有邮箱/OAuth 注册。
9. 注册码使用后状态变为 `used`，再次发送仍返回原码，不重新发码。
10. 已被公众号发放的注册码不能被管理员删除。
11. 新表由启动迁移自动创建，不修改既有用户表结构。
12. 提供部署配置和微信公众号后台配置说明。
