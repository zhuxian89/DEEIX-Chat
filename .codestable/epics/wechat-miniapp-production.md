# 微信小程序正式客户端

## 起点

DEEIX Chat 已有成熟的 Web 客户端、Go HTTP API、统一用户、会话、订阅、计费、模型、对话和文件体系。独立 `miniapp/` 技术验证已经采用 Taro 4.2.1、React 18.3.1、TypeScript strict 与 Webpack 5，并在微信开发者工具和真机完成现有后端的 Bearer 鉴权、内存 refresh Cookie 轮换、连续流式对话、独立生图和鉴权文件下载验证。

验证工程仍是面向既有邮箱账号的技术探针，不具备正式产品导航、微信一键登录、生产身份映射、完整聊天体验或上线安全边界。现有 Web 注册继续强制使用微信公众号发放的注册码；本 Epic 不合并公众号、Web 与小程序身份。

## 目标

在隔离的 `miniapp/` 工程中交付可真机使用的微信小程序正式客户端：用户无需邮箱、密码或注册码即可通过 `wx.login` 一键进入，首次进入时创建标准 DEEIX 用户，后续通过小程序 OpenID 找回同一用户；客户端提供生产级会话列表、连续流式聊天和生图/文件体验，并完整复用现有用户 ID 下的订阅、余额、计费、模型权限、对话和文件事实。

小程序登录时若微信返回 UnionID，后端必须保存该标识，为未来跨平台身份融合保留数据；本 Epic 不使用 UnionID 查找、绑定、合并或迁移公众号/Web 账号。

## 范围

- 延续根级 `miniapp/` 的独立 pnpm workspace、lockfile、Taro/React/TypeScript/微信构建边界，不加入根 workspace 或 turbo。
- 新增小程序专用的后端 domain、repository、application、WeChat API client 与 HTTP transport；新增小程序身份绑定表和纯追加配置。
- 新增公开的微信小程序登录接口：服务端校验一次性 `wx.login` code，调用微信 `code2Session`，按服务端配置的 AppID 与 OpenID 幂等登录或快捷创建用户。
- 快捷创建标准 `identity_users.id` 及其密码关闭的 credential、默认订阅/计费初始化和用户自有邀请码；不消费注册码，不创建平行用户体系。
- 绑定表保存 AppID、OpenID、可空 UnionID、用户 ID、首次绑定与最近登录时间；当前身份解析只使用 `(app_id, open_id)`。
- 登录成功复用现有 access token、refresh token、session 与审计语义；小程序只在内存持有 access token 和 refresh Cookie，冷启动重新执行 `wx.login`。
- 将验证期网络、内存 Cookie 桥接、分块传输、UTF-8/NDJSON 解析和鉴权下载能力整理为生产模块，删除页面对探针术语、测试账号和手工验证步骤的依赖。
- 交付正式产品壳、会话列表、三种新建入口、历史消息、连续流式回答、停止、错误恢复、Markdown 基础呈现、图片附件、生图结果预览与保存、余额/权限错误反馈。三种入口为“AI 对话”“AI 生图”和次级“更多模型”：前两者隐藏模型概念并使用服务端配置的固定默认模型，后者允许高级用户选择有权限的模型。
- 对新增 HTTP DTO 与接口生成 Swagger 和 TypeScript API contract，并保持 Web 客户端行为不变。
- 建立确定性自动化测试、后端集成测试、微信构建检查和真机验收矩阵。

## 非目标

- 不把公众号 OpenID、公众号注册码记录、Web 邮箱账号与小程序账号自动关联。
- 不使用 UnionID 登录、查找现有用户、合并账号或迁移余额、对话、文件和邀请关系。
- 不在本期提供邮箱绑定、密码设置、Web 登录小程序账号、二维码登录或账号切换。
- 不改变 Web 必须使用微信公众号注册码注册的既有规则，也不修改公众号发码流程和已有表结构。
- 不实现微信支付、充值、订阅消息、手机号授权或微信昵称/头像强制授权。
- 不移植 Web 管理后台、知识库管理、MCP、HTML Artifact、Monaco、Mermaid、PDF/DOCX 完整预览等非核心能力。
- 不重构上游既有用户、认证、计费、账号注销或管理员删除主流程；小程序扩展使用新文件、新表和窄接入点。
- 不提交、不 push、不发布、不申请或修改微信平台资质与线上配置，除非 owner 对相应动作另行明确授权。

## 验收标准

1. 全新安装的小程序无需邮箱、密码、注册码或手工输入即可完成首次登录；首次登录只创建一个标准用户和一条绑定，响应不暴露 OpenID、UnionID、session key、AppSecret 或 refresh token。
2. 同一 AppID/OpenID 的重复、并发和微信重试登录始终返回同一个 `identity_users.id`；用户初始化与绑定在数据库一致性边界内完成，不产生重复用户或可重复领取的新用户权益。
3. 绑定表对 `(app_id, open_id)` 强制唯一，UnionID 可空；首次获得 UnionID 时安全补全，后续值不一致时拒绝静默覆盖并留下脱敏安全审计。
4. 当前登录决策只依据 `(app_id, open_id)`；测试必须证明相同 UnionID 不能在本期自动关联另一个用户。
5. 快捷注册用户使用现有用户 ID 进入现有订阅、余额、模型授权、计费流水、对话和文件体系；一次真实收费模型调用只产生既有语义的一次扣费，不新增小程序专用余额或账本。
6. 绑定记录不随既有硬删除路径级联消失；若绑定指向的用户已不存在或不可登录，同一 OpenID 不得自动创建第二个用户，接口返回稳定的账号不可用错误。
7. 后端仅信任服务端配置的 AppID/AppSecret，不接受客户端指定身份域；`wx.login` code 和微信 session key 不持久化、不写日志，微信接口具备超时、错误码归一化、限流和快捷注册总开关。
8. access token、refresh Cookie 及模型凭据只驻留小程序进程内存；冷启动通过 `wx.login` 静默恢复身份，进程内 refresh 继续使用已验证的轮换桥接，构建产物与日志扫描无敏感值和持久化 token。
9. 冷启动反复登录不会无限累积有效小程序会话；后端对该绑定的旧小程序会话执行有界失效策略，同时不影响用户可能存在的 Web 会话。
10. 会话列表、创建会话、模型权限、历史消息、连续多轮流式对话、停止与可恢复错误在真机可用；中文、Emoji、任意分块边界和中止后的 UI 状态正确。
11. 生图与普通对话互不捆绑；用户可选择可用图像模型、独立发起/停止生成、预览结果，并通过已配置的合法 downloadFile 域名保存或查看鉴权图片。
12. 新增 API 完成 Swagger/contract 生成，`pnpm api:check` 通过；后端相关测试、小程序类型检查、单测、生产微信构建、隔离 checker 和产物安全扫描全部通过。
13. 现有 Web 邮箱登录、Web 注册码注册、公众号发码、邀请、账号删除和管理员删除回归测试通过，相关既有表结构和公开行为不变。
14. 真机至少验证：首次一键登录、杀进程后恢复为同一用户、余额/订阅一致、一段连续多轮对话、停止、一张图片生成与下载、网络切换后的明确恢复；每项记录环境、结果和限制。
15. 隐私政策、用户协议入口、生成式 AI 内容提示、必要的平台类目/备案/审核清单形成可执行上线检查表；未满足的外部门槛不得包装为代码完成。
16. 新建入口优先展示“AI 对话”和“AI 生图”，用户一次点击即可创建固定模型会话；“更多模型”作为次级入口，仅列出当前用户有权限且已启用的模型。默认模型 ID 由小程序专属服务端配置提供，不硬编码在客户端；配置变更只影响新会话，既有会话不换模，默认模型不可用时明确报错且不得静默切换到价格不同的模型。

## 共享语言与概念边界

- **小程序一键登录**：客户端调用 `wx.login` 获取短期一次性 code，由 DEEIX 后端向微信换取身份并签发现有 DEEIX 会话。
  - 不包括：把 code、OpenID 或 session key 当作 DEEIX access token；使用公众号 OpenID；要求用户填写邮箱、密码或注册码。
  - 不变量：客户端不能声明 AppID、OpenID、UnionID 或用户 ID，身份事实只能来自服务端配置和微信服务端响应。
- **快捷注册用户**：首次出现的 `(app_id, open_id)` 创建的标准 DEEIX 用户，其 credential 的密码能力关闭，暂不具备 Web 邮箱密码登录能力。
  - 不包括：独立小程序用户表、影子余额、影子订阅或匿名临时用户。
  - 不变量：所有业务外键继续指向同一个 `identity_users.id`。
- **身份绑定**：`wechat_miniapp_bindings` 中小程序身份到标准用户 ID 的不可猜测映射。
  - 不包括：公众号发码关系、OAuth/OIDC identity link、跨用户账号合并。
  - 不变量：AppID 与 OpenID 共同界定当前登录身份；绑定历史保留，账号删除后不得用同一微信身份重新领取新用户资格。
- **UnionID 留档**：微信 `code2Session` 实际返回 UnionID 时保存其原值及观察时间。
  - 不包括：当前登录匹配条件、唯一用户推断、公众号/Web 绑定或自动纠错。
  - 不变量：空值不阻止登录；已保存非空值变化属于安全异常，不能静默覆盖。
- **平台融合**：未来另立 Epic 后，才可能使用已保存的 UnionID、邮箱验证或明确授权的合并流程连接公众号、Web 与小程序身份。
  - 不包括：本 Epic 的任何运行时分支或隐藏自动合并。

端到端边界场景：一个从未使用 DEEIX 的微信用户首次打开小程序，客户端无表单执行 `wx.login`；服务端换取 OpenID 与可选 UnionID，在单一一致性边界内创建标准用户、密码关闭的 credential、默认业务初始化和绑定，签发现有会话。用户完成一轮付费对话和一次生图，扣费、消息和文件均归属该用户 ID。杀死小程序后再次进入，服务端通过相同 AppID/OpenID 返回原用户，补全但不使用 UnionID，并使旧小程序会话保持有界。即使数据库中另有相同 UnionID 的账号，本期也不得自动连接。

## 关键决策

- **DEC-1 · 独立 Taro 正式客户端**：延续已通过真机验证的 Taro 4.2.1、React 18.3.1、TypeScript strict、Webpack 5 和独立 pnpm workspace；不以 WebView 或复用 Next.js/React 19 组件替代小程序 UI。
- **DEC-2 · 同一业务用户体系**：快捷注册创建标准 `identity_users.id`，既有计费、订阅、模型、对话、文件和邀请代码生成语义继续以该 ID 为权威；不建立平行账本。
- **DEC-3 · OpenID 当前登录、UnionID 仅留档**：当前只按服务端 AppID 与小程序 OpenID 绑定；UnionID 可空保存，任何跨平台关联明确移出本 Epic。
- **DEC-4 · 小程序通道免注册码**：微信小程序快捷注册不消费公众号或管理员注册码；Web 注册码政策完全不变。通过独立开关、微信 code 交换、唯一绑定、限流和删除后不重建控制开放注册风险。
- **DEC-5 · 新表保留身份历史**：`wechat_miniapp_bindings` 是 fork 自有身份事实，不向既有用户表加列，不依赖既有删除流程清理；绑定指向已删除用户时拒绝重新注册，避免重复权益与身份劫持。
- **DEC-6 · 复用认证签发而不复制密码登录**：小程序 transport/application 作为可信微信身份入口，调用认证包中以新文件提供的窄会话签发能力，复用现有 session、JWT、refresh 轮换和审计；不复制 token 算法或改造 `/auth/login`。
- **DEC-7 · 内存会话与冷启动静默重登**：客户端不持久化 refresh token；进程内使用已验证的内存 Cookie 桥接，冷启动重新 `wx.login`，后端只让该绑定的小程序有效会话保持有界，不注销 Web 会话。
- **DEC-8 · 只迁移契约和行为语义**：正式客户端复用生成 API 类型、服务端资源 ID 与已验证的纯 TypeScript 流解析逻辑；页面、状态和平台能力按 Taro 重写，不导入 DOM/browser-only Web 组件。
- **DEC-9 · 对话与生图独立交互**：两类能力共享模型目录、会话/文件/计费契约，但分别发起、停止和呈现；不存在“一键测试”或强制捆绑调用。
- **DEC-10 · 最小上游冲突面**：业务实现优先进入新的 `wechatminiapp` 包、模型和 `miniapp/` 文件；数据库迁移、配置装配和路由注册只允许纯追加窄接入，不修改既有表结构、密码登录、Web 注册、公众号、删除或计费框架行为。
- **DEC-11 · 任务入口优先于模型入口**：普通用户只需选择“AI 对话”或“AI 生图”，由服务端小程序配置解析并固定本会话模型；“更多模型”保留给高级用户。客户端不硬编码默认模型、不向快捷入口暴露供应商术语，也不在默认模型故障时静默改用不同价格的模型。

## 整体验收

- UnionID 被安全保存但没有任何跨平台匹配行为；Web 注册码注册和公众号发码保持原样。
- 本 Epic 的新增后端事实集中在小程序新表/新包和必要的纯追加装配点，未修改既有表结构、账号删除、管理员删除、密码登录、Web 注册或计费框架。

## 遗留风险

- 小程序免注册码意味着开放一个新的公开注册通道；唯一 OpenID 只能限制单个微信身份，不能消除批量微信账号滥用，生产默认权益、限流阈值和运营监控仍需结合真实流量调整。
- 微信 `code2Session` 是否返回 UnionID受微信平台配置影响；本期允许为空，未来平台融合不能假设历史记录全部具备 UnionID。
- 冷启动静默重登会增加 session 审计记录；本期必须限制有效小程序会话数量，但历史会话保留和清理周期继续遵循现有认证体系。
- 微信基础库、iOS/Android 网络和分块行为可能变化；已验证的原生逃生口与确定性解析测试必须保留，不能只依赖开发者工具。
