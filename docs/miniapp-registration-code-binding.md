# 公众号注册码与小程序独立绑定

同一个公众号 `REG-…` 注册码可用于网站注册一次、小程序开启聊天一次，两者互不消耗。已用于网站注册的码仍能开通小程序。每个码最多绑定一个 `AppID + OpenID`，绑定后永久有效。两端仍是独立账号，余额、订阅和聊天记录不合并。

## 使用入口

在公众号获取注册码和小程序码，识别进入「随风待办」，打开「我的 → 反馈与建议」，粘贴完整注册码并提交。服务端返回开启状态后，现有小程序自动进入聊天页面。这里使用当前正式版的实际菜单名称「反馈与建议」。

## 存储与并发

- 新表 `miniapp_registration_code_bindings` 以 `registration_code_id` 为主键，`app_id + open_id` 为组合唯一索引，保存 `bound_at`；不保存明文注册码，没有用户或注册码外键。
- 只读校验 `registration_codes` 中状态为 `active` 或 `used` 的码，并要求存在 `wechat_registration_issuances` 发放记录。后台单独创建、未通过公众号发放的码不能用于此入口。
- 不更新网站码的状态、使用者或使用时间，不改变网站注册和微信登录流程，不改上游表结构。
- 按微信身份取得事务锁，在同一事务中写入新绑定和 `miniapp_entry_unlocks` 永久记录。跨身份抢同一码由数据库唯一约束裁决；失败整体回滚。
- 同一身份重复提交返回原开启时间，已开启身份提交另一码不消耗新码。重启、清缓存、换手机后按微信身份恢复状态。
- 已有固定口令授权保持有效。`REG-…` 输入优先走独立校验，失败不回退到共享口令；注册码不依赖 `miniapp_todo:feedback_code` 配置。
- 继续使用既有认证和限流，身份来自服务端微信绑定，不能由反馈请求指定。普通反馈正文和注册码不存入反馈表，注册码查询不写 SQL 日志。

## 部署

部署包含本功能的后端，启动时自动创建新表；数据库账号须有建表权限。无需手工 SQL、无需新增配置，也无需为本次改动重新上传小程序。已有二维码素材和图片回复配置可以继续使用。

## 验证

默认数据库测试使用 SQLite 多连接，覆盖网站状态不变、重复提交、跨身份抢码、同身份抢多个码、事务回滚和重启恢复。设置 `MINIAPP_TEST_POSTGRES_DSN` 指向**测试库**后，运行 `go test ./internal/infra/persistence/miniapptodo -run TestRegistration -count=1 -v` 可验证 PostgreSQL；每个用例自动创建并清理独立 schema，不应将此变量指向生产库。

HTTP 测试验证不能伪造 OpenID，失败返回既有 `miniapp_todo.invalid_code`，成功保持现有响应契约。手机端仍需验收实际入口跳转和二维码识别。
