# 小程序 TODO 首页与共享码解锁

状态：本地实现、自动化验证和独立复审已完成；尚未部署，待 PostgreSQL 环境和微信真机验收。更新日期：2026-09-10。

## 已确认的行为

普通用户默认进入「AI省着用」的 TODO 首页。「我的 → 反馈与建议」提供普通反馈和独立的体验码输入框。所有人使用共享码 `666`，服务端去除首尾空格后校验。不同微信身份都可使用，不消费码，不建立发码后台。

一次解锁后永久保存。同一 AppID、同一微信账号清缓存或换手机后，从服务端恢复并直接进入原 AI 页面。解锁没有到期时间。已有记录再次提交时保留首次解锁时间，无需重新校验码。

**本版不做微信提醒。** 没有订阅授权、消息模板、发送接口、后台提醒任务或提醒表。保留任务日期、时间和逾期提示。未来每人一码另行设计。

## 与现有业务的边界

现有微信登录、令牌、AI 接口、会话、模型权限和计费保持原样。TODO 仅控制默认页面分流；用户明确接受登录时已具有完整 AI 能力。旧 AI 路径 `pages/index/index` 保留，不新增 AI 权限检查。

新入口使用现有 `wx.login → /api/v1/auth/wechat-miniapp/login` 和刷新接口；只查询 TODO 入口状态，不初始化模型、聊天或计费。解锁后 `reLaunch` 原页面，由它按原流程初始化。

新接口复用既有认证和限流。服务端从当前登录用户只读查询当前配置 AppID 对应的 `wechat_miniapp_bindings`，取得未撤销的 OpenID。客户端不提交归属身份。旧表不增加字段、索引或外键，不修改旧登录响应。

## 页面和交互

| 入口 | 内容 |
| --- | --- |
| 待办 | 今天、近七天、全部、重要筛选、逾期分组、折叠已完成、搜索、添加任务 |
| 清单 | 默认收件箱；新建、改名、上移排序；删除清单时将任务移入收件箱 |
| 任务详情 | 标题、备注、重要标记、清单、日期、时间、一层步骤、重复规则、删除 |
| 我的 | 已完成记录、文本复制、CSV 导出、同步状态、反馈与建议 |
| 反馈与建议 | 普通反馈单独提交；体验码在单独输入框校验，不自动写入反馈正文 |

采用浅绿背景、深色文字、系统字体和简洁列表。UI 方向已使用 `ui-ux-pro-max` 核对；主要点击区域至少 44 个逻辑像素（750 设计宽度下为 88 样式单位），底部导航和添加按钮适配安全区，表单使用原生输入与选择器。

日期按日历日期保存，首版界面统一使用北京时间，包括今天、明天快捷选择和逾期判断。全天任务次日才逾期，有具体时间的任务按该时间判断。工作日仅指周一至周五。完成有未完成步骤的父任务时先确认，所有步骤完成不会自动完成父任务。完成与删除提供撤销，删除采用软删除。

重复规则支持每天、工作日、每周指定日、每月指定日。完成本次后创建一个下一实例，保留本次历史；逾期完成跳到未来，不补建所有遗漏实例。月底不足 31 日时使用月末，后续仍保留 31 日锚点。下一实例复制未删除的步骤并清空完成状态。

重复任务撤销仅在下一实例及其步骤未修改时执行；已有修改则返回冲突，页面可选择云端版本或保留为普通新待办。

## 永久解锁和独立新表

| 新表 | 用途 |
| --- | --- |
| `miniapp_entry_unlocks` | AppID + OpenID 组合主键，首次解锁时间，无到期时间 |
| `miniapp_todo_lists` | 身份 + 清单 ID，名称、顺序、版本和软删除时间 |
| `miniapp_todo_tasks` | 身份 + 任务 ID，版本、查询字段、完整任务数据和软删除状态 |
| `miniapp_todo_operations` | 身份 + 操作 ID，请求摘要、处理回执，用于安全重试 |
| `miniapp_todo_feedback` | 身份、正文、处理状态、创建时间 |

五张表全部由 `backend/internal/infra/persistence/miniapptodo` 私有模型维护。没有用户表外键，没有邀请码库存、核销或独立认证表。

通过 fork 自有入口 `backend/internal/app/companion.go` 追加注册，在小禾开关判断之前调用 `registerMiniappTodo`。后者创建新 Store 并迁移上述五张表，再注册接口。迁移失败则返回启动错误，不修改公共 `schema.Models()`、数据库连接代码或上游 `app.go`。关闭小禾时，TODO 仍然迁移和注册，原语音接口仍需认证。

PostgreSQL 迁移使用模块专属事务 advisory lock。业务写入同样按身份取得数据库事务锁；SQLite 在读取版本前取得写入保留锁。重启重复迁移保留已有数据。

## 同步、缓存和容量

每次操作带稳定 ID、实体 ID、基础版本和内容。任务变更和回执在同一事务提交；重复 ID + 同内容返回既有结果，重复 ID + 不同内容拒绝。冲突操作保留本地分支，不能依据设备时间静默覆盖。

页面修改先落入本机队列，再更新显示。同步逐项发送并取得快照，恢复网络和返回前台时重试。冲突暂停队列，用户选择云端内容或将本地内容保存为新待办。编辑页保留打开时的版本，远端更新不会替它自动提高版本号。

客户端对子任务完成、删除和撤销的投影与服务端级联条件一致，使用包含操作 ID 的本机标记区分不同操作。撤销只恢复由对应父操作改变且未再次修改的步骤，不复活此前单独删除的步骤。

不同已验证身份的缓存完全隔离，不自动合并。身份切换时重建页面状态，旧草稿、搜索结果和异步回调不会进入新身份。冷启动必须先在线确认当前微信身份；登录不可用时显示重试，不打开上一次身份的缓存。确认身份之后，当前页面可离线编辑并在联网后同步。不持久化访问令牌或刷新 cookie。

待办正文保存到身份隔离的本地文件，写完后更新小型缓存索引；更新索引失败保留旧文件和旧数据。这样避免微信单个缓存 key 的 1 MB 限制。[Taro 缓存说明](https://docs.taro.zone/docs/3.x/apis/storage/setStorage)

服务端活跃任务上限为 5000 项、完整活跃数据 4 MiB；快照另附最近 100 项完成或删除记录供撤销。历史与搜索分页查询，每页最多 100 项。单次导出使用一个数据库查询取得一致的内容，最多 10000 项、8 MiB，超限提示缩小范围。客户端列表分批显示，容量失败不会删除待同步队列。

## 新接口与代码归属

所有路径以 `/api/v1` 开头，沿用既有 JSON 响应封装。小程序 DTO 引用生成的 `@deeix/api-contract` 类型。

上述新增接口必须通过 GitHub 的 Workspace Quality 检查。该工作流在根目录执行 `pnpm check`，其中 API 契约包会重新生成并比较 Swagger 和 TypeScript 类型。七个接口均在 `handler.go` 中声明 Swagger 注释；接口改动后运行 `pnpm api:generate`，一并保留 `backend/docs/docs.go`、`backend/docs/swagger.json`、`backend/docs/swagger.yaml` 和 `packages/api-contract/src/types.generated.ts`，再以 `pnpm api:check` 验证一致性。工作流已覆盖 `backend/**` 和 `packages/**`，新增接口无需单独添加 CI job。

| 接口 | 用途 |
| --- | --- |
| `GET /miniapp-entry/status` | 解锁状态和不暴露 OpenID 的缓存标识 |
| `POST /miniapp-entry/unlock` | 共享码校验、永久解锁 |
| `GET /miniapp-todo/snapshot` | 活跃待办与近期记录 |
| `POST /miniapp-todo/sync` | 操作去重、版本校验和同步回执 |
| `GET /miniapp-todo/tasks` | 搜索、清单筛选、完成状态、历史分页 |
| `GET /miniapp-todo/export` | 文本或 CSV 导出 |
| `POST /miniapp-todo/feedback` | 普通反馈 |

后端新包分布在 `domain/miniapptodo`、`application/miniapptodo`、`infra/persistence/miniapptodo` 和 `transport/http/miniapptodo`；小程序新增 `pages/entry`、`components/todo`、`product/todo` 和 `platform/todo-cache.ts`。既有业务的接入只修改 fork 注册入口和小程序页面配置；相邻启动测试更新为新的组合注册行为。

- 清缓存后从服务端恢复默认 AI 入口；普通 TODO 启动不依赖模型列表或聊天初始化。
- 新表重复迁移、事务回滚、跨身份操作拒绝、回执去重、重复任务并发和子任务撤销由后端测试覆盖。
