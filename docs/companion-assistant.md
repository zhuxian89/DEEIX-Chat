# 小禾：全局理解与事项跟进

本次扩展在小禾模块内完成，依赖配套后端和小程序版本。入口为小禾聊天页的“记忆与跟进”。已根据微信后台截图准备日程提醒模板的本地部署配置，尚未部署到服务器或完成真机送达验证。应用内跟进可独立运行；服务端加载配置并获得用户授权后才能发送微信通知。

直接对话创建的定时及重复提醒采用独立调度，详见 [对话提醒](companion-reminders.md)。以下后台整理周期和安静模式约束仅适用于自动跟进，不影响用户明确设置的提醒。

## 行为

- 首页保留已送达的招呼，并可预览最近的到期跟进。聊天页定期读取已持久化的主动消息；切后台后回来可恢复。
- 前端主动请求异常等待 30 秒重试，服务端聊天接话尝试间隔至少一分钟；无候选时前端等待五分钟。成功接话按消息轮次去重，新的聊天轮次可再次参与。原来的正常/少主动频次、已读、停顿和结束语约束继续生效。
- 已读请求成功后才确认已读；失败后十秒重试。“查看主动联系状态”显示最近一次首页、聊天、跟进和通知的处理原因。
- 全局理解默认读取同账号的其他会话及当前小程序绑定身份的待办。可关闭或排除指定会话；关闭后仍可理解与小禾自己的对话。排除或关闭读取范围会取消相应派生跟进，手动创建的事项保留。
- 只把成功的用户消息作为用户事实来源，限定当前账号、未删除会话和消息、最新分支祖先链。附带会话标题、来源标识和时间；引用、角色扮演和示例由提取提示排除，保留原话依据供用户核对。
- 关键词检索最多检查 24 个候选会话；每个会话最多取 8 条匹配用户消息，总计最多 24 条。常规读取向前追溯最多 128 个节点，关键词查询最多 2048 个节点；最多补足到 32 条会话/待办资料，每条最多 800 字。不是全部历史扫描或语义搜索，未召回不代表用户没有说过。
- 有截止日期的待办自动形成跟进，按待办时区解析；只有日期时默认当天 09:00。待办改期、完成、删除或去掉日期后会同步更新，同一待办保留同一跟进 ID。
- 会话中明确的个人计划由配置的聊天模型整理，要求确切日期、逐字依据；每次最多四条，自动事项不能超过未来 90 天。可以识别对既有事项的改期、完成和取消，结果以列表为准。模型语义理解仍可能出错，不能仅凭聊天里的承诺当作已经设置成功。
- 跟进支持手动添加、修改时间、完成和取消；手动创建最多一年内。用户编辑后标为“由你管理”，模型不会覆盖该事项，后续请在列表调整。关联待办被完成或删除仍会停止提醒。
- 日期输入和显示固定 UTC+8，不在每条消息旁重复标注时区。

## 调度与可靠性

后台每 30 秒启动一个有界批次，按账号游标每批最多十人，批次最多四分钟。自动提取每账号最多十分钟一次，仅在资料指纹变化时调用模型，单次最多 20 秒；无变化不反复推理。新计划因此可能需要等待下一轮整理，急用可手动添加。服务重启继续使用数据库中的事项、指纹和发送记录。

发布前先同步待办、核对最新会话资料。会话资料尚未处理成功时暂缓自动会话事项，避免按旧计划通知；手动和待办事项不依赖模型提取成功。到期后每轮每账号最多发送一条，超过 24 小时的积压标为过期。“我先开口”暂停主动聊天和到期提醒。账号停用/注销、来源删除、排除、遗忘或旧分支均不能继续触发对应提醒。

跟进写入小禾专属主动消息时间线，不写普通消息表。发布使用账号租约、行写锁、事项版本和事务，一次到期只记录一次。改标题不会重发，改时间或重新激活会重新安排；旧版本编辑返回冲突。保留最近 100 条主动消息，列表最多展示 200 条事项，同时待跟进最多 100 条。

已读、候选、到期写入失败可在后续周期重试。微信发送则采用保守的单次尝试：在事务内占用一次授权，再调用微信。失败或进程崩溃后的不确定结果标记为未确认，不自动补发，避免重复打扰；应用内消息仍保留。通知是尽力送达，不是严格实时闹钟。

删除或纠正记忆同时推进全局遗忘时间，删除从旧资料形成的跟进并清除派生文案，防止旧资料被全局检索重新注入。普通聊天原文仍可查看；新发表的内容可重新作为资料。

## 微信订阅配置

复用服务端现有小程序 AppID、AppSecret 和有效账号绑定，密钥不下发到客户端。新增环境配置仅位于小禾注册模块：

| 配置 | 含义 |
| --- | --- |
| `DEEIX_COMPANION_NOTIFICATION_TEMPLATE_ID` | 在微信公众平台申请的真实一次性订阅模板 ID |
| `DEEIX_COMPANION_NOTIFICATION_TITLE_FIELD` | 模板的事项字段，本次为 `thing5` |
| `DEEIX_COMPANION_NOTIFICATION_TIME_FIELD` | 模板的时间字段，本次为 `time30` |
| `DEEIX_COMPANION_NOTIFICATION_STATE` | `formal`（默认）、`trial` 或 `developer` |

当前适配需要一个仅由事项和时间两个字段组成的兼容模板。事项最长 20 字，时间格式 `YYYY-MM-DD HH:mm`；通知打开小程序首页。未配模板、字段不兼容或启动时缺少凭据时，接口报告 `ready=false`，按钮不可授权。

仓库根目录的 [docker-compose.companion.yml](../docker-compose.companion.yml) 已填写上述值。它是独立覆盖文件，需叠加到当前部署实际使用的 Compose 文件上；没有修改原有 Compose 文件。部署时须先准备包含本次提醒功能的后端镜像及配套小程序，不能假设现有远程 `latest` 镜像已经包含未发布的本地代码。

例如，使用默认 Compose 的部署在确认镜像后加载：

```bash
docker compose -f docker-compose.yml -f docker-compose.companion.yml up -d app
```

使用 `docker-compose.full.yml` 或 `docker-compose.sqlite.yml` 的部署应替换第一个文件名，保持原有数据库、存储和网络配置。模板参数通过容器环境变量传入后端；只把它们写进根目录 `.env` 或 `config.yaml` 不会自动启用发送。直接运行后端时，需将以上四项设置为该后端进程的环境变量。

覆盖文件默认使用正式版 `formal`。开发版验收需将 `DEEIX_COMPANION_NOTIFICATION_STATE` 设为 `developer`，体验版设为 `trial`；Compose 可从启动环境或 `.env` 读取该覆盖值。该值指定通知点击后打开的小程序版本，不控制调度时间。模板、字段及版本环境变更后须重建后端容器，直接运行的后端则须重启。

配置生效后，在小禾“记忆与跟进”确认通知状态就绪，再点击“允许下一次提醒”，授权后创建一条短时提醒验收。截图及本地适配测试只能确认字段映射，不能替代微信账号归属、用户授权和真机送达验证。

用户点击“允许下一次提醒”才调用微信订阅弹窗，只有返回 `accept` 后才登记授权。后端校验配置的模板和当前账号绑定，一次最多保留一份待用授权，不累加客户端声称的次数；微信平台仍是实际授权的最终校验方。授权绑定具体 AppID、OpenID 和模板；更换绑定后不会继承旧授权或旧身份的待办跟进。消耗后需再次订阅，用户也可主动关闭。

发送适配器使用微信 `stable_token` 获取并缓存 token，错误信息不输出 token、密钥或完整请求 URL。自动测试只使用本地 HTTP 模拟服务，不触发真实用户通知。

## 数据与接口

新增 `companion_context_preferences`、`companion_followups`、`companion_decisions`、`companion_notifications` 四张小禾自有表；原小禾主动频次表追加成功轮次标记。未修改上游账号、会话、消息、认证和计费表结构，也未增加其删除流程钩子。账号残留清理由小禾后台自行执行。

鉴权与限流沿用已有 `/api/v1/companion` 路由组：

- `GET /assistant`：来源、跟进、读取偏好、诊断和通知就绪状态。
- `PATCH /assistant/context`：全局开关及排除会话。
- `GET /assistant/conversations?q=&page=1`：当前账号可选择的其他会话，每页 50 条。
- `POST /assistant/followups`：新增或按 `revision` 更新事项。
- `POST /assistant/notifications`：记录真实订阅选择或关闭通知。

公开契约由 Swagger 生成，内部账号 ID、OpenID、AppSecret 和数据库租约不出现在上述 DTO 中。

真实模型的计划理解、实际模板字段兼容性和微信真机送达需要在配置及部署后联合验收；本地测试和构建不代表已发布或已完成真机验收。
