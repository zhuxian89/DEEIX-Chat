# 小伴 v1：独立助手模块

首版已完成启动接入。经 owner 确认，`app.go` 仅追加以下三行启动注册。前端只有在助手接口可用后才显示首页入口，不会对旧后端展示失效入口。

## 唯一启动接入点

已在 `backend/internal/app/app.go` 的 `platformhttp.NewEngine(...)` 错误处理之后、后台 worker 启动之前追加：

```go
if err := registerCompanion(engine, db, runtimeCfg, authService, conversationService, rateLimiter, shutdownSignal, log); err != nil {
    return nil, err
}
```

注册实现、鉴权、限流、迁移和路由全部在新增的 `backend/internal/app/companion.go`。可设置 `DEEIX_COMPANION_ENABLED=false` 关闭模块；关闭后不注册路由、不建表。默认使用后台的小程序对话模型配置，未配置时使用平台默认聊天模型。接入需要后端发布，不能只上传小程序验证功能。

## 本版体验

- 一个固定的 AI 朋友“小伴”，无角色定制、skill 编辑或模型选择界面。
- 首页空闲两秒后出现招呼卡片，不弹窗。只在前台提供开场；打字、翻看记录、正在生成时不主动插话。
- 开场至少间隔 12 小时；没回应上次招呼、仍有未读回复时不追加。可以关闭主动开场。
- 自然接话，一次最多问一个问题，不要求每轮提问，不催回复，不假装真人。具体自然度仍需用配置的真实模型验收。
- 图片上传与文字可一起发送，助手的文字和图片附件可一起显示。原生生图需要配置的聊天模型支持图片输出；本版不另开一次自动收费的生图任务。
- 专属记忆可查看依据、纠正、删除或全部忘记。全部忘记不删除聊天原文；原文仍可在历史中查看。

## 上游同步边界

新增 `companion_profiles`、`companion_memories` 两张表；不修改用户、会话、消息、计费等原表的列或索引。

聊天原文、附件、生成任务、审核和计费仍使用原有系统，通过新的助手接口调用原聊天 handler。助手模块只保存映射、开场状态、摘要、记忆、并发租约。普通聊天接口、账号框架和计费流程没有被改写。

两个适配文件也全部为新增：

- `application/conversation/companion.go`：创建一次请求专用的聊天服务外观，注入固定角色与专属上下文，复用运行与计费能力。
- `infra/persistence/postgres/conversation/companion.go`：提供读取记忆待整理消息的有界游标，兼容 SQLite/Postgres。

小程序新增组件与客户端；原首页只增加入口/页面分支，原 session 只增加助手路径选择与混合图片完成结果识别。接口使用原 `SendMessageRequest`、run ID、NDJSON 事件、完成响应、续传及取消路径。Web 暂无对应助手页面；本版助手行为只在专用助手接口生效。普通 Web 会话页打开同一聊天原文时仍是普通聊天。

## 记忆边界与成本

上下文 = 固定角色 + 最近最多 24 条消息 + 最多 1800 字摘要 + 最多 12 条近期/相关记忆，并继续经过模型上下文预算检查。最多保存 60 条记忆，每条最多 120 字，1–90 天有效；摘要超过 30 天不再注入。

成功聊过至少四轮后才尝试整理记忆。每位用户最多每五分钟一次，每个服务实例最多同时两次，每次最多处理 32 条新消息；按游标向前处理，繁忙聊天不会直接跳到末尾。每次整理超时 25 秒，失败保留旧状态，后续聊天可重试，不影响已完成的回复。输入和输出都复用内容审核；记忆必须引用对应用户原话，助手的猜测不能成为依据。模型仍可能理解错误，因此保留依据和纠正入口。

招呼使用内置文案，不调用模型、不扣用户余额。记忆整理由平台承担模型调用成本；用户聊天沿用已有计费。长聊天的历史原文仍保留，当前页面展示最近 100 条；本版未新增更早历史的分页界面。

删除或纠正记忆会清空摘要，并把上下文/提取起点推进到当前消息之后。并发整理通过版本校验拒绝旧结果回写；旧普通会话摘要、召回片段和 provider 续接状态不会在助手接口重新注入。用户之后主动再次提供同一信息时，可以形成新记忆。

账号删除继续由上游负责；模块每小时清理最多 100 个已不存在账号的助手数据，只删除自己的两张表，不修改账号删除流程。没有订阅消息、离线触达或消息推送任务。

验证结果：上述后端相关包测试通过；助手存储测试的 `-race` 检查通过；小程序 129 项测试、类型检查、构建和产物检查通过；API 契约检查通过。完成三行启动接入后，再次通过 `go test ./internal/app`、全量后端构建和 `pnpm api:check`。

本次并行检查时，默认后端构建在链接阶段遇到 Windows 虚拟内存不足；其余检查完成后，使用进程级 `GOMEMLIMIT=512MiB`、`GOGC=50`、`GOMAXPROCS=2` 单独执行 `go build -p 1 ./...` 通过，未修改项目或系统配置。

重点检查：用户隔离、并发租约、摘要/记忆上限与过期、删改后的旧任务回写、顺序提取长聊天、已有消息祖先不被修改、前台空闲条件、混合图片附件识别和接口契约。

代码检查和构建不能替代微信真机验收。后端发布后，需要验收首次开场、忽略后不催促、切后台后返回恢复、键盘/滚动、图文消息与记忆删除；本轮未声称这些真机阶段完成。
