# 小伴 v1：独立助手模块

首版已完成启动接入。经 owner 确认，`app.go` 仅追加以下三行启动注册。前端只有在助手接口可用后才显示首页入口，不会对旧后端展示失效入口。

## 唯一启动接入点

已在 `backend/internal/app/app.go` 的 `platformhttp.NewEngine(...)` 错误处理之后、后台 worker 启动之前追加：

```go
if err := registerCompanion(engine, db, runtimeCfg, authService, conversationService, rateLimiter, shutdownSignal, log); err != nil {
    return nil, err
}
```

注册实现、鉴权、限流、迁移和路由全部在新增的 `backend/internal/app/companion.go`。可设置 `DEEIX_COMPANION_ENABLED=false` 关闭模块；关闭后不注册路由、不建表。默认使用后台的小程序对话模型配置，未配置时使用平台默认聊天模型。接入需要后端发布，不能只上传小程序验证功能。

## 本版体验

- 一个固定的 AI 朋友“小伴”，无角色定制、skill 编辑或模型选择界面。
- 首页空闲两秒后出现招呼卡片，不弹窗。只在前台提供开场；打字、翻看记录、正在生成时不主动插话。
- 开场至少间隔 12 小时；没回应上次招呼、仍有未读回复时不追加。可以关闭主动开场。
- 自然接话，一次最多问一个问题，不要求每轮提问，不催回复，不假装真人。具体自然度仍需用配置的真实模型验收。
- 图片上传与文字可一起发送，助手的文字和图片附件可一起显示。原生生图需要配置的聊天模型支持图片输出；本版不另开一次自动收费的生图任务。
- 专属记忆可查看依据、纠正、删除或全部忘记。全部忘记不删除聊天原文；原文仍可在历史中查看。
- 每轮注入北京时间、星期和时段，历史消息携带原始北京时间；按原话日期理解“明天”等相对时间，并区分聊天间隔与跨了几个日历日。
- 主动话题参考明确兴趣与反馈，提供“喜欢这类／少聊这类”，来源链接和报道日期在聊天里展示；聊天可按需联网查证。

## 时间、兴趣与联网

默认时区固定为北京时间 UTC+8，不依赖服务器时区或容器的 zoneinfo 文件。分早晨、上午、午间、下午、晚上、深夜六个时段；首次介绍和回访问候有各自文案。时间作为背景，提示模型尊重用户主动说明的海外或夜班作息，不反复报时或催睡。记忆保存原话的时间；整理摘要时要求相对日期按原话日期转换，缺少依据时不补造日期。

首版推荐是可解释的兴趣排序，覆盖科技科普、影视、音乐、游戏、体育、文化旅行六类。明确喜欢和不喜欢是强信号，普通提及和当前话题只作辅助；较新的明确说法优先。五分之一的用户日允许尝试其他未被拒绝的类别。这里还没有协同过滤、观看时长采集或细分兴趣模型，不能声称已达到短视频平台的推荐精度。

“喜欢／少聊”反馈通过 `POST /api/v1/companion/topics/feedback` 提交，只接受本用户已展示话题的 URL。反馈写入原有助手记忆，保留依据、可纠正删除，和其他记忆共用 60 条上限；并发版本检查阻止旧整理任务覆盖反馈。普通对话中的明确偏好沿用至少四轮后的记忆整理节奏，按钮反馈立即生效。拒绝类别不会被探索排序重新选中；弱信号不会覆盖拒绝。

后台须启用 MCP，配置 active 的 Exa 服务和 `web_search_exa`，可选同服务的 `web_fetch_exa`；聊天模型须支持工具调用。助手只自动选择这两个工具，继续通过原聊天运行时执行和计费，不接受客户端任意指定工具。开发环境的 Exa MCP 与产品后台配置相互独立；本次开发环境已实测搜索成功，未读取或复制该连接的凭据到生产后台。

开场搜索只发送内置公开类别、当前日期和来源要求，不把用户聊天原文或完整记忆发给搜索引擎。每个类别使用跨用户、跨实例共享缓存：成功后最多每小时刷新一次，失败等待五分钟，每个服务实例最多一项刷新、22 秒超时；仅由前台打开或聊天触发，无离线推送。普通开场立即返回，冷缓存先提供时间问候，后台准备后供后续聊天或符合频率规则的开场使用。

候选只采用限定来源的 HTTPS 报道，要求明确发布日期在过去 48 小时内，缓存超过两小时不用作新鲜话题。外部文本送入既有审核与临时聊天链路生成短开场，结果须引用对应来源原文作为依据；引用关系不代表机器已证明所有事实或语义。来源发布日期不等于事件发生日期，模型提示明确要求区分。首次见面、深夜、刚聊过、表达难过或拒绝时回退到普通问候；新闻开场最多每 24 小时一次，最近 20 条 URL 去重，并继续受原 12 小时、未读和未回应限制。

可设置 `DEEIX_COMPANION_TOPICS_ENABLED=false` 关闭主动话题检索与新话题开场，普通时间问候和用户聊天的按需联网仍可用。自动开场的搜索、摘要由平台承担费用；用户聊天中的模型和 MCP 调用按原平台计费。

设计参考：[Google 开场设计](https://developers.google.com/assistant/conversation-design/greetings)、[TikTok 推荐信号与多样性说明](https://newsroom.tiktok.com/en-us/how-tiktok-recommends-videos-for-you)、[Exa 搜索接口与日期过滤](https://exa.ai/docs/reference/search)。

## 上游同步边界

模块拥有 `companion_profiles`、`companion_memories`、`companion_topic_caches` 三张表；此次仅在前两张助手自有表追加时间与话题状态，新增共享公开话题缓存表。不修改用户、会话、消息、计费等上游表的列或索引，原 `app.go` 接入无需再次调整。

助手按仓库分层约束组织：`domain/companion` 保存不带 JSON/ORM 标签的数据与英文错误；`application/companion` 定义存储接口并处理用例；`infra/persistence/companion` 独立持有 GORM 模型、迁移、租约、事务和账号残留清理；`transport/http/companion/dto.go` 映射公开 JSON 字段。重构保留表名、列名、唯一索引和 HTTP 字段，不调整架构守护测试或上游基础框架。

聊天原文、附件、生成任务、审核和计费仍使用原有系统，通过新的助手接口调用原聊天 handler。助手模块只保存映射、开场状态、摘要、记忆、并发租约。普通聊天接口、账号框架和计费流程没有被改写。

适配文件也全部为新增：

- `application/conversation/companion.go`：创建一次请求专用的聊天服务外观，注入固定角色与专属上下文，复用运行与计费能力。
- `application/conversation/companion_web.go`：发现后台现有 Exa 工具，复用凭据解密、地址校验和 MCP 客户端。
- `infra/persistence/postgres/conversation/companion.go`：提供读取记忆待整理消息的有界游标，兼容 SQLite/Postgres。

小程序新增组件与客户端；原首页只增加入口/页面分支，原 session 只增加助手路径选择与混合图片完成结果识别。接口使用原 `SendMessageRequest`、run ID、NDJSON 事件、完成响应、续传及取消路径。Web 暂无对应助手页面；本版助手行为只在专用助手接口生效。普通 Web 会话页打开同一聊天原文时仍是普通聊天。

## 记忆边界与成本

上下文 = 固定角色与时间 + 最近最多 24 条带日期的消息 + 最多 1800 字摘要 + 最多 12 条近期/相关记忆 + 最多 2 条带来源和日期的话题，并继续经过模型上下文预算检查。最多保存 60 条记忆，每条最多 120 字，1–90 天有效；摘要超过 30 天不再注入。

成功聊过至少四轮后才尝试整理记忆。每位用户最多每五分钟一次，每个服务实例最多同时两次，每次最多处理 32 条新消息；按游标向前处理，繁忙聊天不会直接跳到末尾。每次整理超时 25 秒，失败保留旧状态，后续聊天可重试，不影响已完成的回复。输入和输出都复用内容审核；记忆必须引用对应用户原话，助手的猜测不能成为依据。模型仍可能理解错误，因此保留依据和纠正入口。

当前限制：24 条近期消息窗口尚未与摘要覆盖游标联动。快速连续聊天或摘要失败时，尚未整理的消息可能先退出模型上下文；原文仍在数据库中。自动追赶摘要及按需检索更早原文尚未实现，不能保证长聊细节始终连续。

普通时间问候使用内置文案，不调用模型、不扣用户余额。记忆整理和缓存话题准备由平台承担成本，用户聊天沿用已有计费。长聊天的历史原文仍保留，当前页面展示最近 100 条；本版未新增更早历史的分页界面。

删除或纠正记忆会清空摘要，并把上下文/提取起点推进到当前消息之后。并发整理通过版本校验拒绝旧结果回写；旧普通会话摘要、召回片段和 provider 续接状态不会在助手接口重新注入。用户之后主动再次提供同一信息时，可以形成新记忆。

账号删除继续由上游负责；模块每小时清理最多 100 个已不存在账号的助手档案和记忆，不修改账号删除流程。公开话题缓存按固定类别覆盖，不含用户数据。没有订阅消息、离线触达或消息推送任务。
